# 01-架构设计

本文档详细介绍 Galay MCP 的架构设计、核心组件和设计理念。

## 整体架构

Galay MCP 采用分层架构设计，从底层到上层依次为：

```text
┌─────────────────────────────────────────────────────────┐
│           应用层 (Application Layer)                     │
│  McpClient/Server  │  McpClient/Server         │
├─────────────────────────────────────────────────────────┤
│           协议层 (Protocol Layer)                        │
│  JSON-RPC 2.0 消息处理  │  MCP 方法路由                 │
├─────────────────────────────────────────────────────────┤
│         编解码层 (Codec Layer)                           │
│  serde JSON DOM  │  StreamWriter (序列化)              │
├─────────────────────────────────────────────────────────┤
│          传输层 (Transport Layer)                        │
│  Stdio (stdin/stdout)  │  HTTP (Galay-HTTP)             │
├─────────────────────────────────────────────────────────┤
│           基础层 (Foundation Layer)                      │
│  Galay-Kernel  │  Galay-Utils                           │
└─────────────────────────────────────────────────────────┘
```

## 核心组件

### 1. 传输层

#### Stdio 传输

- **实现**: 基于标准输入输出流
- **消息格式**: 每行一条 JSON-RPC 消息，以换行符分隔
- **适用场景**: 进程间通信、命令行工具、管道连接
- **特点**: 简单、轻量、易于调试

```cpp
// 消息示例
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{...}}\n
```

#### HTTP 传输

- **实现**: 基于 Galay-HTTP 框架
- **消息格式**: HTTP POST 请求，Body 为 JSON-RPC 消息
- **适用场景**: 网络服务、微服务架构、远程调用
- **特点**: 标准化、可扩展、支持负载均衡

```http
POST /mcp HTTP/1.1
Content-Type: application/json

{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{...}}
```

### 2. 编解码层

#### JSON 解析 (serde)

- **高性能**: 使用 SIMD 指令加速解析
- **零拷贝**: DOM 视图避免不必要的内存分配
- **类型安全**: 提供类型检查和转换

```cpp
// 解析示例
auto doc = JsonDocument::parse(jsonString);
if (doc) {
    const auto& root = doc->root();
    if (root.is_object()) {
        auto value = root["key"].as_string();
        if (!value) return std::unexpected(McpError::invalid_params(value.error()));
    }
}
```

#### JSON 序列化 (StreamWriter)

- **流式写入**: 边构建边输出，内存占用小
- **类型安全**: 编译期类型检查
- **高效**: 避免中间字符串拼接

```cpp
// 序列化示例
std::string output;
auto writer = make_json_writer(output);
// StreamWriter 错误粘滞，最终 finish() 会报告此前任一步的失败。
(void)writer.start_object();
(void)writer.key("result");
(void)writer.number(42);
(void)writer.end_object();
const auto finished = writer.finish();
if (!finished) return std::unexpected(McpError::internal_error(finished.error()));
```

### 3. 协议层

#### JSON-RPC 2.0

遵循 JSON-RPC 2.0 规范，支持：

- **请求 (Request)**: 带 ID 的方法调用，需要响应
- **响应 (Response)**: 对请求的回复，包含结果或错误
- **通知 (Notification)**: 不带 ID 的方法调用，无需响应

```cpp
// 请求结构
struct JsonRpcRequest {
    std::string jsonrpc = "2.0";
    std::optional<int64_t> id;
    std::string method;
    std::optional<std::string> params;
};

// 响应结构
struct JsonRpcResponse {
    std::string jsonrpc = "2.0";
    int64_t id;
    std::optional<std::string> result;
    std::optional<std::string> error;
};
```

#### MCP 方法路由

支持的 MCP 方法：

| 方法 | 说明 | 类型 |
|------|------|------|
| `initialize` | 初始化握手 | Request |
| `notifications/initialized` | 初始化完成通知 | Notification |
| `ping` | 心跳检测 | Request |
| `tools/list` | 获取工具列表 | Request |
| `tools/call` | 调用工具 | Request |
| `resources/list` | 获取资源列表 | Request |
| `resources/read` | 读取资源 | Request |
| `prompts/list` | 获取提示列表 | Request |
| `prompts/get` | 获取提示 | Request |

### 4. 应用层

#### 服务器端

**McpStdioServer**:
- 同步阻塞模型
- 从 stdin 读取请求，向 stdout 写入响应
- 线程安全的工具/资源/提示注册表
- 支持动态添加工具、资源和提示

**McpHttpServer**:
- 异步协程模型
- 基于 Galay-HTTP 的 HTTP 服务器
- 工具处理函数为协程，支持异步操作
- 必须在 `start()` 前完成所有注册

#### 客户端

**McpClient stdio 模式**:
- 同步阻塞模型
- 向 stdout 发送请求，从 stdin 读取响应
- 请求-响应模式，每次调用等待结果
- 线程安全的请求发送

**McpClient HTTP 模式**:
- 异步协程模型
- 基于 Galay-HTTP 的 HTTP 客户端
- 所有操作返回协程，需要 `co_await`
- 支持连接复用和并发请求

## 错误处理

### std::expected 模式

使用 C++23 的 `std::expected` 进行错误处理，避免异常开销：

```cpp
// 返回值或错误
std::expected<std::string, McpError> call_tool(
    const std::string& toolName,
    const std::string& arguments
);

// 使用示例
auto result = client.call_tool("add", args);
if (result) {
    // 成功：使用 result.value()
    std::cout << result.value() << '\n';
} else {
    // 失败：使用 result.error()
    std::cerr << result.error().message() << '\n';
}
```

### 错误类型

```cpp
class McpError {
public:
    McpErrorCode code() const;           // 错误码（枚举类型）
    const std::string& message() const;  // 错误消息
    const std::string& details() const;  // 详细信息

    // 工厂方法
    static McpError parse_error(const std::string& details);
    static McpError invalid_request(const std::string& details);
    static McpError method_not_found(const std::string& method);
    static McpError invalid_params(const std::string& details);
    static McpError internal_error(const std::string& details);
};
```

### 错误码

遵循 JSON-RPC 2.0 错误码规范：

| 错误码 | 说明 |
|--------|------|
| -32700 | 解析错误 |
| -32600 | 无效请求 |
| -32601 | 方法未找到 |
| -32602 | 无效参数 |
| -32603 | 内部错误 |
| -32000 ~ -32099 | 服务器自定义错误 |

## 并发模型

### v2 HTTP 所有权边界

v2 HTTP 不使用跨线程读取的原子共享指针，也不为普通通知调用创建协程：

- McpHttpServer::start() 所在线程拥有订阅链表和 HTTP server 的启动/停止过程。监听协程通过现有 MPSC 命令队列提交注册，外部线程的通知函数也只提交值命令；owner 在线程循环中处理命令并广播。
- 通知函数返回成功表示命令已入队，不表示任何订阅者已收到事件。订阅事件继续使用有界队列；队列满时沿用丢弃该事件的行为。命令队列不可用或分配失败时通过 std::expected<void, McpError> 返回错误。
- 监听协程为订阅节点分配满足事件队列对齐要求的独占存储，并通过命令将所有权交给 start owner；owner 负责链接和回收，监听协程仅借用节点并在结束时发布完成标志。服务停止会关闭命令入口和订阅事件队列，等待借用者退出后再停止 HTTP runtime。调用 stop() 会阻塞，应从外部线程调用；销毁前必须 join start() 线程。
- 工具、资源、提示注册表和 server 配置必须在 start() 前由单线程设置；运行期间只读。
- McpHttpClient 的 HTTP transport 与工具定义表由构造时捕获的 runtime.get_io_scheduler(0) owner 独占。请求和 listen() 必须在该 owner 上执行；错误线程返回 InvalidParams，重叠请求返回 Overload。connect() / close() 是普通检查函数，返回底层 transport task；调用方必须在 owner 上立即 await 到完成，再执行其他客户端操作。

### Stdio 模式

- **服务器**: 单线程事件循环，顺序处理请求
- **客户端**: 使用互斥锁保护请求发送，支持多线程调用
- **线程安全**: 工具/资源/提示注册表使用读写锁

```cpp
// 服务器主循环
void McpStdioServer::run() {
    while (m_running) {
        auto message = read_message();  // 阻塞读取
        if (message) {
            handle_request(*message);    // 处理请求
        }
    }
}
```

### HTTP 模式

- **服务器**: 协程异步模型，每个连接一个协程
- **客户端**: 协程异步模型，支持并发请求
- **线程安全**: 基于 Galay-Kernel 的调度器

HTTP router 交付已解析的 `HttpRequest`，通过 `body_str()` 读取 body，响应通过
`get_writer()` / `send_response()` 发送。下面的 `process_async` 是应用 helper，
返回 `kernel::Task<void>`，将 JSON 结果写入引用，不是 `HttpConn` 的成员。

```cpp
kernel::Task<void> handle_mcp_http(http::HttpConn& conn, http::HttpRequest request) {
    std::string response_json;
    const auto processed = co_await process_async(request.body_str(), response_json);
    if (!processed) co_return;

    http::HttpResponse response;
    response.set_body_str(std::move(response_json));
    const auto header_result = response.header().header_pairs().add_header_pair(
        "Content-Type", "application/json");
    if (header_result != http::HttpErrorCode::kNoError) co_return;
    auto writer = conn.get_writer();
    for (;;) {
        const auto sent = co_await writer.send_response(response);
        if (!sent || *sent) break;
    }
    co_return;
}
```

## Schema 构建器

提供链式 API 简化 JSON Schema 构建：

```cpp
auto schema = SchemaBuilder()
    .add_string("name", "User name", true)
    .add_number("age", "User age", false)
    .add_enum("role", "User role", {"admin", "user"}, true)
    .add_array("tags", "User tags", "string", false)
    .build();
```

生成的 Schema：

```json
{
  "type": "object",
  "properties": {
    "name": {
      "type": "string",
      "description": "User name"
    },
    "age": {
      "type": "number",
      "description": "User age"
    },
    "role": {
      "type": "string",
      "description": "User role",
      "enum": ["admin", "user"]
    },
    "tags": {
      "type": "array",
      "description": "User tags",
      "items": {"type": "string"}
    }
  },
  "required": ["name", "role"]
}
```

## 性能优化

### 1. 零拷贝解析

使用 serde 的 JSON 子值视图，避免再复制整份 DOM：

```cpp
// 不拷贝原始 JSON
const auto& element = doc.root();
if (!element.is_object()) return std::unexpected(McpError::invalid_params("object required"));
const auto child = element["key"];  // 子值持有原 DOM 存储
```

### 2. 缓存机制

服务器在注册更新时缓存工具/资源/提示列表，不在请求热路径重新序列化。
下面是 `McpStdioServer::add_tool` 内部的缓存更新片段：

```cpp
m_toolsListCache = protocol::build_list_result_from_map(
    m_tools, "tools",
    [](const ToolInfo& info) -> const Tool& { return info.tool; });
```

### 3. 流式序列化

使用 serde StreamWriter 流式构建 JSON，避免另一套手写序列化器：

```cpp
std::string output;
auto writer = make_json_writer(output);
// 错误粘滞，所有写入结果由最终 finish() 统一检查。
(void)writer.start_object();
for (const auto& item : items) {
    (void)writer.key(item.name);
    (void)writer.string(item.value);
}
(void)writer.end_object();
const auto finished = writer.finish();
if (!finished) return std::unexpected(McpError::internal_error(finished.error()));
return output;
```

### 4. 协程异步

HTTP 模式使用协程避免线程阻塞：

```cpp
// request 已由 router 解析；process_async 是上文的应用 helper。
std::string response_json;
const auto processed = co_await process_async(request.body_str(), response_json);
if (!processed) co_return;
// 接着按上文通过 get_writer() / send_response() 发送 response_json。
```

## 扩展性设计

### 1. 自定义传输层

可以实现自定义传输层，只需遵循消息格式：

```cpp
class MyTransport {
public:
    // 读取一条消息
    std::expected<std::string, McpError> read_message();

    // 写入一条消息
    std::expected<void, McpError> write_message(const std::string& msg);
};
```

### 2. 自定义工具处理

工具处理函数可以执行任意操作：

```cpp
// Stdio 模式：同步处理
server.add_tool("my_tool", "Description", schema,
    [](const json::Json& args) -> std::expected<std::string, McpError> {
        // 同步处理逻辑
        return result;
    }
);

// HTTP 模式：异步处理
server.add_tool("my_tool", "Description", schema,
    [](const json::Json& args, std::expected<std::string, McpError>& result)
    -> kernel::Task<void> {
        // 异步处理逻辑
        auto data = co_await fetch_data_async();
        result = process_data(data);
    }
);
```

### 3. 自定义资源读取

资源读取函数可以从任意来源获取数据：

```cpp
server.add_resource("file:///data.txt", "Data file", "Data file resource", "text/plain",
    [](const std::string& uri) -> std::expected<std::string, McpError> {
        // 从文件系统、数据库、网络等读取
        return read_from_source(uri);
    }
);
```

## 设计原则

### 1. 类型安全

- 使用强类型而非字符串魔法值
- 编译期类型检查
- `std::expected` 显式错误处理

### 2. 零成本抽象

- 内联小函数
- 避免虚函数开销
- 编译期优化

### 3. 易用性

- 链式 API（SchemaBuilder）
- 合理的默认值
- 清晰的错误消息

### 4. 可扩展性

- 插件式工具注册
- 自定义传输层
- 灵活的处理函数

### 5. 标准兼容

- 遵循 MCP 2024-11-05 规范
- 遵循 JSON-RPC 2.0 规范
- 使用标准 C++23 特性
