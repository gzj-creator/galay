# Serde 重构设计：普通结构体直接读写 JSON 和 TOML

状态：JSON 和 TOML 的免注册映射随 serde `v0.6.0` 发布，Galay 的 gitlink 锁定该版本。分析基线为 serde `v0.5.1`（`d0327a1`）。

## 1. 结论与范围

**需要重构 serde：让 JSON 和 TOML 共享字段发现，不重写 `reflect` 的显式契约或任何解析器。**
普通结构体不应该先重复声明字段才能做 JSON 或 TOML 往返。反过来，对外协议必须能固定字段名、选择输出字段、
描述约束，不能让内部结构体新增一个成员就改变协议。这两类需求应当在 serde 内区分：

- **普通数据**：保留 `json::serialize` / `json::deserialize<T>` 和 `toml::serialize` / `toml::deserialize<T>`。同一个简单聚合结构体在两种格式下都不要求注册、模板特化或包装类型。
- **显式协议契约**：继续用 `reflect_fields` 提供重命名、排除、验证及 OpenAPI 需要的元数据。显式契约仍可供两种格式复用。
- **首期边界**：两种格式的文本往返同批交付，保留各自的语法、字段语义和资源限制。不为 JSON 流式写入增加自动映射，不改 simdjson、TOML 解析器、Schema 生成或 HTTP 绑定，不要求 C++26。

实现落在 Galay 实际构建的独立 serde 子模块工作树。Galay 的 [`galay::serde` 构建目标][galay-target] 只接线；不在 Galay 再维护一套编解码 API，也不在本次实现中更新 submodule 的锁定提交。

## 2. 为什么不是重写 `reflect`

当前[快速开始](00-快速开始.md)中已经有简单的读写调用；额外负担是每个结构体还要写 `#define ...`、
`REFLECT_FIELDS`、`#undef`。这份字段列表实际承担了两种职责：让编解码器找到成员，以及声明跨格式或对外协议的字段契约。

| 现有代码 | 实际职责 | 重构后的边界 |
| --- | --- | --- |
| serde [`reflect.hpp`][reflect-source] | ADL 查找 `reflect_fields`，提供字段名、成员指针、取值、约束及静态元数据 | 继续表示**显式**契约；不把所有聚合类型变成 `reflect::Reflectable` |
| serde [`json.hpp`][json-source] | 递归编解码、查字段、生成错误；simdjson 负责解析 | 编解码器从共享适配层拿字段，复用现有对象分支与快速索引 |
| serde [`toml.hpp`][toml-source] | 递归编解码，以及表、内联表和表数组的表示与输出 | 从同一适配层拿字段；保留表语义，不经 JSON 中转 |
| [`galay-doc`][doc-source] | 用静态契约生成 OpenAPI，并按成员指针绑定 HTTP 参数 | 不消费自动字段；文档与绑定继续要求稳定、显式的描述符 |
| [`galay-mcp`][mcp-source] | 显式 wire DTO、字段策略及 `to_wire` / `from_wire` 转换 | 保留字段名、缺省规则和 wire 类型，不让普通聚合映射改变协议 |

`reflect::StaticReflectable` 不只是“编译期能看见字段名”的标记。OpenAPI 与绑定代码还需要比较描述符、识别同一个成员指针。
Boost.PFR 提供按索引取成员的引用，不能将其当作成员指针来替代这一契约。

## 3. 最终使用方式

### 普通结构体：无注册 JSON / TOML 往返

以下写法自 serde `v0.6.0` 起可用：

```cpp
#include <iostream>
#include <string>
#include <serde/json/json.hpp>
#include <serde/toml/toml.hpp>

struct User {
    int id{};
    std::string name;
    bool operator==(const User&) const = default;
};

int main() {
    const User input{.id = 42, .name = "Alice"};
    const auto json_text = json::serialize(input);
    if (!json_text) {
        std::cerr << json_text.error() << '\n';
        return 1;
    }
    const auto from_json = json::deserialize<User>(*json_text);
    if (!from_json) {
        std::cerr << from_json.error() << '\n';
        return 1;
    }

    const auto toml_text = toml::serialize(input);
    if (!toml_text) {
        std::cerr << toml_text.error() << '\n';
        return 1;
    }
    const auto from_toml = toml::deserialize<User>(*toml_text);
    if (!from_toml) {
        std::cerr << from_toml.error() << '\n';
        return 1;
    }

    std::cout << *json_text << '\n' << *toml_text;
    return *from_json == input && *from_toml == input ? 0 : 1;
}
```

JSON 输出：

```json
{"id":42,"name":"Alice"}
```

TOML 输出：

```toml
id = 42
name = "Alice"
```

使用模块的程序改用 `import json;` 和 `import toml;`，不额外导入反射模块或 Boost.PFR。头文件与模块两种消费方式以现有 serde 规则为准。

### 对外协议：显式列出允许读写的字段

以下写法已由当前 serde 支持。描述符和类型定义放在同一头文件，或从同一个模块导出，确保在所有实例化点可见：

```cpp
#include <string>
#include <tuple>
#include <type_traits>
#include <serde/reflect/reflect.hpp>

namespace api {

struct UserResponse {
    int id{};
    std::string display_name;
    std::string internal_note;
};

constexpr auto reflect_fields(std::type_identity<UserResponse>) {
    return std::tuple{
        reflect::make_field("id", &UserResponse::id),
        reflect::make_field("displayName", &UserResponse::display_name),
    };
}

}
```

调用方式不变。JSON / TOML 的输出都只含 `id` 与 `displayName`；`internal_note` 不会被自动补入，也不会通过输入赋值。
两种格式可共享 `reflect::make_field` 的字段名和约束；`json::FieldPolicy` 与 JSON 的 wire 转换仍只对 JSON 生效。
普通映射输出所有参与映射的公开成员，**不会自动识别敏感字段**；新增或重命名成员可能同时改变输出与必填输入。
因此持久化格式、公开 HTTP API、MCP 报文不要直接复用可随业务改动的普通结构体。

## 4. 方案选型

| 方案 | 能解决什么 | 决策 |
| --- | --- | --- |
| [reflect-cpp][reflect-cpp] | 普通聚合结构体直接 `rfl::json::write` / `read<T>` | 借鉴调用体验；不替换 serde 的后端、错误或字段契约 |
| [Glaze][glaze] | 普通结构体无需元数据；可用 `glz::meta` 显式定制 | 借鉴自动和显式两类映射分工；不引入第二套 JSON 实现 |
| [Boost.PFR][boost-pfr] | 提供编译期 `tuple_size_v<T>`、`get_name<I, T>()`、`get<I>(object)`；不依赖整个 Boost | 采用独立 `boost-1.89.0`，只用于 JSON/TOML 共享的内部字段发现 |
| [C++26 静态反射 P2996][p2996] | 语言级成员枚举与名字获取 | 不提高本次最低标准；如将来具备一致的工具链支持，再评估替换内部实现 |

C++23 没有可移植的标准接口能列出结构体的成员名。[PFR 的字段名提取有适用限制][pfr-limits]，因此不手写编译器签名解析，
也不把 `std::is_aggregate_v<T>` 当作“任意聚合类型均受支持”。首期支持命名空间作用域的简单聚合结构体：公开且可赋值的数据成员、可默认构造，
没有基类、引用成员、`const` 数据成员、位域、联合或 C 数组。成员类型仍由各格式现有编解码器决定；首期覆盖标量、`std::string`、
`std::optional`、`std::vector`、`std::array`、字符串键 map 和嵌套结构体。`std::array` 本身走现有数组分支，不做对象映射。

类型筛选只负责排除可判定的不适用类型，不自行写一套聚合检测器；不可反射的边界形状可能在模板实例化时由编译器诊断。
不丢字段、不在编译失败或编解码失败后改用另一种映射。运行业务数据错误仍由 `std::expected` 返回。

## 5. 内部结构

### 共享字段发现，而不是共享解析和输出

1. 两个格式各自保留现有内建类型、容器和包装类型分支，例如 TOML 日期时间、`InlineTable<T>`，以及 JSON 的 `Json`、`RawValue` 和 ADL wire 转换。容器和普通包装类型将当前映射策略传给元素，不会因其自身是聚合类型就改变输出。
2. 进入对象分支时，如类型有 `reflect_fields`，使用现有描述符，通过 `.name` / `.get(object)` 访问，保留字段约束和 wire 策略。
3. 仅在允许自动映射且该类型没有显式描述符时，使用 PFR 生成编译期描述符。每项只有名字和按索引取成员的能力，不生成 `.pointer`、约束或 wire 策略。
4. 同一格式中的两种描述符进入现有对象编解码流程；都不适用时沿用 `unsupported type` 行为，不输出空对象或空表来隐藏错误。

显式契约应约束整个 DTO，而不仅是某一层的字段名。例如协议 DTO 的 `items` 是 `std::vector<Item>`，`Item` 没有显式描述时不应突然可以序列化。
因此 JSON/TOML 普通读写从根允许自动映射；**进入显式 DTO、JSON 的 ADL wire 类型或按描述符挑选字段的 API 后，其子树只允许显式对象契约**。
普通聚合可以含有显式 DTO；从该显式节点向下按同一规则处理。内建类型和容器仍可用。该选择用一个内部编译期策略传递，
不新增 `ParseOptions` 开关、第二套公开 API 或运行时探测。特别是 `json::decode_field`、`json::decode_fields_into` 继续只接受现有契约。

### 实现落点

| 位置（相对 serde 根目录） | 实施内容 |
| --- | --- |
| `src/reflect/detail/object_fields.hpp`（新增） | 两个编解码器共享。例如用 `tuple_size_v` 生成索引序列，再用 `get_name` / `get` 生成 `.name` / `.get(object)` 描述符。对 `const` 对象取只读引用，对解码目标取可赋值引用。字段名是编译期常量，字段发现不额外分配内存 |
| `src/json/json.hpp` | 复用 `encodeValue` 的对象分支和 `decodeValue` → `decodeFieldsInto` 的解码分支。内部的静态字段索引接受自动描述符，`reflect::StaticReflectable` 的公开含义不变；运行时描述符处理不动 |
| `src/toml/toml.hpp` | 复用对象的 `encodeValue` / `decodeValue`，字段赋值与严格未知字段检查都走同一来源。`vector` / `array` 的 `array_table` 标记与元素的对象映射选择一致；保留 `tableArray` 对真实节点形状、空数组和内联表的检查 |
| `src/reflect/reflect.cppm` 和格式门面 | 两个头文件入口包含同一内部适配头；模块构建在 `reflect` 全局模块片段包含 PFR，再通过现有模块提供 `reflect::detail` 内部模板。`json` / `toml` 沿用现有导入，不增加公开模块或签名里的 PFR 类型 |
| `src/reflect/reflect.hpp`、`src/json/stream.hpp` | 保持公开反射契约和流式写入的支持范围。流式自动映射若后续有需求，再接入共享适配层，不改写 writer |

### 两种格式行为约定

| 情形 | JSON | TOML |
| --- | --- | --- |
| 字段名与顺序 | 自动字段使用成员原名，按键名读取，不承诺声明顺序 | 同样使用成员原名，按键名读取；表的组织与字段输出顺序沿用现有 writer |
| 非可选字段缺失 | 返回缺字段错误；有 C++ 默认初始化器也不视为可省略 | 相同 |
| `std::optional` | 缺键保留 `T{}` 的初始化值；显式 `null` 清空；空 optional 输出 `null` | 缺键保留初值，空 optional 字段省略；数组里的空 optional 仍报错，不能用 `null` 占位 |
| 文档结构 | 普通对象输出 JSON object，真正的空结构体输出 `{}` | 文档根仍须是表；空结构体可输出空文档。子结构体用 `[section]`，非空结构体数组用 `[[items]]`，空数组输出 `[]`，已有 `InlineTable<T>` 用于显式要求内联表示 |
| 未知键与重复键 | 默认忽略未知键、拒绝重复键；沿用 `ParseOptions`。`decode<T>` 不重新解析已有 `Json` | 默认忽略未知键，严格模式拒绝；重复定义仍是语法错误 |
| 语法、类型、范围与限制 | 沿用现有诊断和资源限制，失败用 `std::expected` 返回 | 相同；保留 TOML 有符号 64 位整数范围与日期时间格式，不借 JSON 值模型放宽 |

[TOML 没有 `null` 值][toml-spec]。若 `std::optional<int> retries = 3;` 被调用方主动清空，TOML 序列化省略该键，读取会恢复默认的 `3`，
不是空值。这个差异在现有契约就存在；不新增占位值或默认值覆盖规则。反序列化失败时，两种文本 API 都不交付部分构造的对象。

## 6. 打包与升级

延续 serde 随源码交付第三方依赖的做法，将 PFR 独立头分发放在 serde 的 `third_party/boost_pfr/`，记录上游版本和校验值并携带许可证。
不下载整套 Boost，不隐式拾取系统头或在配置时联网。PFR 只提供模板，不增加新的运行时链接库。
vendored 副本通过可复现的机械替换隔离 include 路径、命名空间和配置宏，不改字段提取逻辑，避免下游自己的 Boost.PFR 与 serde 混用头文件。

- **CMake**：头文件与 `import json;` / `import toml;` 的构建目标、安装目标都传递同一份 PFR 头。验证安装后的独立工程不依赖原始源码目录或系统 Boost。
- **mcpp / Bazel**：由 serde 自己声明 include 路径和依赖可见性，Bazel 沙箱只读声明过的头；Galay 仍通过现有依赖目标消费。mcpp 不将 `json` 指定为唯一库根模块，使 `toml` 和 `json` 都作为公开模块消费。
- **升级顺序**：先在独立 serde 仓库实现、验证和发布；再更新 Galay 的 gitlink、对应 `MODULE.bazel` 版本、快速开始与示例。mcpp 的 path 依赖由 gitlink 固定，不另外在 `mcpp.lock` 中记录。不要在 Galay 保留补丁版后端或两套字段注册 API。

## 7. 交付步骤与验收

| 步骤 | 交付物 | 完成标准 |
| --- | --- | --- |
| 1. 锁定行为与基线 | 在 serde 补无注册结构体的 JSON/TOML 往返测试与显式契约隔离测试；记录显式路径基线 | 无宏往返测试在旧版确实失败；既有 `json_contract`、`field_contract`、`toml_stream_contract` 与 JSON 流式测试通过 |
| 2. 实现最小端到端 | 先以 JSON 接通共享适配，再接 TOML 表、表数组和解码；显式节点锁定子树 | 同一个示例读写两种格式都能回到原值；不新增用户注解、运行期类型表或第二套解析流程 |
| 3. 验证消费与回归 | serde 多构建入口、安装消费者和 Galay 集成测试 | Linux 的 GCC、Clang/libc++，以及 macOS AppleClang 的受支持头文件路径通过；Linux 的现有模块路径验证通过；无法获得字段名的受支持工具链不得静默降级 |
| 4. 发布后接入 Galay | 更新统一依赖引用，普通 JSON 示例与显式协议示例分别展示 | `serde`、`api`、`mcp`、`etcd` 相关回归通过；OpenAPI 输出与协议 fixture 无非预期变化；共享后端仍只有一份 |

必须覆盖的测试：

- **共同往返**：两字段结构体、交换输入键序、空结构体、嵌套 DTO、容器中的 DTO、缺失 optional 保留默认值。两种格式读回结果都要检查，不只比输出文本。
- **格式差异**：JSON 显式 `null` 和宽字段查找；TOML 测子表、内联表、`std::vector` / `std::array` 的表数组、空数组、空 optional 省略与数组拒绝，以及日期时间的专用表示。断言已清空但有非空默认值的 optional 按格式分别还原。
- **错误输入**：缺必填字段、错误类型、严格模式未知键、重复键、非对象 JSON、TOML 超范围整数和现有资源限制。断言 `value.profile.id` 等层级诊断。
- **契约隔离**：两个格式都验证显式改名、排除、约束、容器子对象不自动映射；JSON 另测既有 wire 转换。OpenAPI 仍只接受显式静态契约，JSON 流式不扩大支持范围。覆盖多个翻译单元使用同一显式 DTO。
- **性能**：用现有结构体双格式基准、JSON 宽字段和分配基准比较显式路径，另测等价的普通 DTO。用相同编译器、优化参数和输入记录耗时、分配次数与编译时间；显式路径不增加每次调用的分配，超出测量波动的回退须定位。这里不承诺吞吐提升。

初始验证入口：独立 serde 的 CMake `ctest`（头文件、模块、安装消费）、mcpp 锁定构建和 Bazel 测试；
Galay 集成侧以现有 [serde 验证入口](00-快速开始.md#验证) 和相关模块回归为准。

### 8.1 本地性能对照

Linux + GCC 14.2，`-O3`，相同输入与 simdjson 后端。使用 Galay 的 `b1_struct_formats`，
每轮每项 150,000 次、固定同一 CPU，取 5 轮中位数。普通结构体组只移除字段注册，样本值和操作相同。

| 操作（次/秒） | `v0.5.1` 显式 | 重构后显式 | 重构后免注册 |
| --- | ---: | ---: | ---: |
| JSON 编码 | 435,999 | 439,476 | 438,460 |
| JSON 解码 | 862,260 | 868,446 | 865,069 |
| TOML 编码 | 425,230 | 422,361 | 422,384 |
| TOML 解码 | 325,341 | 327,994 | 328,356 |

64 字段 JSON 仅解码在两版显式路径上分别约为 394,801 和 401,469 次/秒；分配基准的显式路径前后相同：
JSON 每次 7 次分配、521 字节，TOML 每次 36 次分配、4,848 字节。结构体基准三组各单次编译用时分别为
15.09 秒、15.66 秒、14.41 秒，峰值内存约为 526、581、585 MiB。本机样本未显示可见的运行时回退，
但增加了编译内存占用；这些数字不是跨平台性能保证。

`v0.6.0` 发版时以同一组可执行文件交替复测（固定同一 CPU、每项每轮 20 万次、取 7 轮中位数）；
相对 `v0.5.1`，四项吞吐显式路径为 +0.14% 至 +0.84%，免注册为 -1.27% 至 +1.21%。
