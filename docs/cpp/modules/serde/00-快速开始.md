# galay-serde

使用独立 [serde](https://github.com/gzj-creator/serde) 依赖，将结构体直接转换为
JSON 或 TOML。Galay 仅提供构建接线，源码、命名空间、反射宏和模块名均由 serde 维护。

## 结构体转换

```cpp
#include <serde/json/json.hpp>
#include <serde/toml/toml.hpp>
#include <serde/reflect/reflect_macros.hpp>

struct Config {
    std::string host;
    int port{};
};

#define CONFIG_FIELDS(X) X(host) X(port)
REFLECT_FIELDS(Config, CONFIG_FIELDS)
#undef CONFIG_FIELDS

std::expected<std::string, std::string> encode(const Config& config) {
    return json::serialize(config); // 换成 toml::serialize 即输出 TOML。
}

std::expected<Config, std::string> decode(std::string_view text) {
    return json::deserialize<Config>(text);
}
```

字段只注册一次，两种格式均可使用；支持嵌套结构、容器、可选字段以及
`X(member, "external-name")` 字段重命名。C++23 没有可移植的自动成员枚举，
因此字段注册仍是必需的。语法、类型、缺失必填字段和资源限制错误通过
`std::expected` 返回，调用方检查结果后取值。

完整可运行示例见 `examples/cpp/serde/e1_struct_formats.cc`。

## 构建

- CMake >= 3.28：`GALAY_BUILD_SERDE=ON`，头文件消费者链接 `galay::serde`。
- 原生模块构建及安装后模块消费者要求 CMake >= 3.31，以支持多个消费目标。
  源码构建使用 `thirdparty/serde` Git submodule，安装时一并安装 serde 包。
  外部项目通过 `find_package(galay CONFIG REQUIRED)` 获得依赖。
- CMake 模块：`GALAY_ENABLE_CPP23_MODULES=ON`，支持的工具链下链接
  `galay::serde-modules`，使用 `import json;` / `import toml;`。
- mcpp：使用 `thirdparty/serde` path 依赖，serde 是常规依赖，默认构建也会解析它。
  `serde` feature 启用示例、基准和 `test/cpp/serde` 中的验证目标，`full` 包含它。
  当前 mcpp 版本的 feature 依赖不会稳定保留在 lock 文件中，因此使用常规依赖
  保证 `--locked` 可验证提交。无需创建根目录 `tests`。
- Bazel：头文件 target 为 `//src/cpp/galay-serde:galay-serde`，
  测试为 `//test/cpp/serde:struct_formats`。Bzlmod 使用固定源码归档及校验和。
  Galay 作为外部模块被消费时，需要初始化 Galay 的 `thirdparty/serde` submodule。

同一程序中的 serde 头文件与命名模块消费方式二选一。模块必须与使用方采用
一致的编译器、标准库和异常编译策略；Galay 不通过 serde 禁用整个项目的 C++ 异常。

首次 checkout 后运行 `git submodule update --init thirdparty/serde`。
升级 serde 时在 submodule 中切换提交并提交 Galay 的 gitlink；CMake、Bazel 和
mcpp 都从同一个 submodule 目录读取源码。

## 共享后端

serde、MCP 和 etcd 共用 serde 提供的 simdjson 后端。Galay 代码通过
`<serde/json/json.hpp>` 使用 serde 的 JSON 接口，CMake target 为 `serde::serde`。
Galay 不保留第二份后端源码。simdjson 的异常接口关闭，解析错误显式处理；
这与调用方自身是否启用 C++ 异常是独立的编译设置。

## 验证

```bash
ctest --test-dir build -L serde --output-on-failure
mcpp build --features serde --toolchain llvm@22.1.8 --locked
mcpp run test_serde_struct_formats --features serde
mcpp run test_serde_import --features serde
bazel test //test/cpp/serde:struct_formats
```

mcpp 的 `run` 使用所选默认工具链；使用 LLVM 验证时，可在本地设置
`[toolchain] default = "llvm@22.1.8"`，或直接运行上一条 build 生成的测试程序。
本机 GCC 16 的 mcpp module mapper 在包含中文源码路径时报告
`INCLUDE-TRANSLATE` 错误，mcpp 模块验证采用 LLVM 22.1.8。

`serde.install_consumer` 验证安装后独立工程的头文件、模块和共享后端消费。
`benchmark_serde_b1_struct_formats` 分别测量 JSON/TOML 结构体编码和解码，
可传入迭代次数；预热和测量均检查错误并输出结果校验值。
