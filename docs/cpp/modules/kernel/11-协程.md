# 11-协程

本页现在只保留 C++ 协程语法在 `galay-kernel` 中的落地点；完整工作流请优先回到主干页。

## 本页回答什么

- 仓库里的公开任务入口是什么
- `co_await task`、`Task<void>::then(...)`、`sleep(...)` 这些能力先看哪里
- 哪些测试 / 示例最适合作为语义锚点

## 当前稳定事实

- 公开返回类型统一为 `Task<T>`
- 等待子任务统一写成 `co_await child_task()`
- 根任务串接统一写成 `task.then(nextTask)`
- `sleep(...)` 依赖运行时中的全局 `TimerScheduler`；涉及时间系统时不要只看本页，要连同主干页一起看
- 子任务完成后，等待者会沿其所属 scheduler 的调度路径恢复，而不是直接跨线程恢复底层句柄
- `JoinHandle::wait()` / `join()` 是阻塞线程的同步入口；协程等待子任务使用 `co_await`

## 阻塞等待与完成通知

`TaskState` 用一个 32 位原子完成状态表示 `kPending`、`kWaiting` 和 `kDone`。
`kWaiting` 只表示已有同步等待注册，任务仍可调度；状态查询使用 `is_done()`，仅
`kDone` 表示完成。任务完成以 release 原子交换发布结果，并只在原状态为
`kWaiting` 时调用 `notify_all()`；同步等待使用 acquire `atomic::wait()` 观察完成。

等待注册与完成操作在同一个原子变量上排序，避免检查完成后、真正入睡前丢失通知。
完成线程无需获取 waiter 的 mutex；同步等待不再分配独立 `TaskWaiter`。该通知机制
使用 C++20 标准原子等待接口，底层休眠与唤醒由平台标准库实现。

并发回归见 `test/cpp/kernel/t198_task_completion_wait_race.cc`，协议分析与本地
测量见 [任务完成通知协议与验证](task_completion_notification.md)。
