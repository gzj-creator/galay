## 本页回答什么

- `Scheduler`、`IOScheduler`、平台后端类的关系是什么

- 去哪里看公开接口与运行时接入方式

## 当前稳定事实

- 平台后端由构建配置自动选择：Linux 为 epoll / io_uring，macOS 为 kqueue；Windows 当前仍为 planned，不提供可用后端
- `IOScheduler` 是按构建后端选出的具体类型别名；`ParallelScheduler` 负责计算协程
- `SchedulerBase<Derived, Type>` 用 CRTP 提供调度器入口，Task/Waker 保存的非拥有 `Scheduler*` 仅在 IO/compute 边界做一次类型分派
- 三个 IO 后端共用 `IOSchedulerBase<Derived, Reactor>` 的线程生命周期、任务队列、唤醒和 IO 注册转发；后端只提供 poll 与延后提交动作
- `IOReadyQueue` 只负责就绪任务、跨线程注入、恢复接纳和工作窃取，不包含 IOController 或 reactor 实现
