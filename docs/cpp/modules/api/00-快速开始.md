# 快速开始

## 构建和运行

要求 C++23、CMake >= 3.28，以及现有 HTTP/kernel 依赖和 serde 0.4.0。
源树消费需要已经初始化并位于已发布 `v0.4.0` 的 `thirdparty/serde`。
先确认现有依赖，不要在当前工作区盲目更新 submodule：

```bash
git -C thirdparty/serde describe --tags --exact-match
git -C thirdparty/serde rev-parse HEAD
```

应分别为 `v0.4.0` 和 `e93269257f04166db056da4ef9ee893d8cc096bf`。
Galay `v6.1.0` 已固定该 serde 发布提交。新 checkout 可运行
`git submodule update --init --recursive` 初始化依赖，再核对上述版本。
已有本地 submodule 改动时先审查状态，不要用更新命令覆盖未提交的工作。
确认依赖后，在现有 Galay 构建配置中启用：

```bash
cmake -S . -B build/api-docs -G Ninja \
  -DCMAKE_CXX_COMPILER=g++-14 \
  -DGALAY_BUILD_API=ON -DGALAY_BUILD_HTTP=ON -DGALAY_BUILD_SERDE=ON \
  -DGALAY_BUILD_EXAMPLES=ON -DBUILD_TESTING=ON
cmake --build build/api-docs --target api_t5_docs example_api_e1_users -j1
ctest --test-dir build/api-docs -R '^api.docs$' --output-on-failure
```

上述配置保留其他模块的现有开关；只需 API 时，可关闭不需要的数据库、
协议模块、C ABI 和 benchmark，避免安装无关依赖。测试目标和示例需要
对应开关开启。低内存环境保持 `-j1`，不要同时启动多个编译任务。

```bash
./build/api-docs/examples/cpp/api/example_api_e1_users --port 8087
curl 'http://127.0.0.1:8087/users/1?verbose=true'
curl -X POST 'http://127.0.0.1:8087/users' \
  -H 'Content-Type: application/json' -d '{"name":"Lin","email":null}'
```

默认只监听 loopback。打开 `http://127.0.0.1:8087/docs` 可使用官方 UI；
`/openapi.json` 返回同一份已经生成的文档。官方
`swagger-ui-dist@5.17.14` 的资源在构建时校验并编译进 `galay-api`，示例不需要
部署额外资源目录，也不依赖源码路径或工作目录；没有目录搜索或 CDN fallback。

## 选择文档策略

类型化服务使用 `<galay/cpp/galay-api/api_server.h>` 中的
`galay::api::ApiServer<Policy>`。默认 `ApiServer<>` 使用 `NoSwagger`，
不自动安装文档路由、不加载 UI；`ApiBuilder::build()` 仍生成可导出的文档。
`NoSwagger` 不移除应用已经手动安装的文档或其他路由。

下面的 `prepared` 来自成功的 `ApiBuilder::build()`；省略应用主线程的
等待和退出逻辑，完整运行示例见 `examples/cpp/api/e1_users.cc`：

```cpp
#include <galay/cpp/galay-api/api_server.h>
#include <utility>

auto config = galay::http::HttpServerBuilder()
    .host("127.0.0.1").port(8087)
    .ioSchedulerCount(1).parallelSchedulerCount(1).buildConfig();
galay::api::ApiServer<> server(config);
auto started = server.start(std::move(prepared));
if (!started) return std::unexpected(std::move(started.error()));
```

启用文档时，将上面的 server 声明替换为以下代码，再检查同一个 `start`
调用的结果。用户示例显式选择此策略，因此实际提供 GET、POST 和文档：

```cpp
galay::api::ApiServer<galay::api::HttpSwagger> server(config);
```

`buildConfig()` 仅导出 HTTP 配置；不要使用会构造既有 `HttpServer` 和
Runtime 的 `build()`。构造 `ApiServer` 不创建 Runtime，`start` 先验证
`PreparedApi` 并安装策略；验证或策略安装失败时仍处于未初始化状态，不创建
Runtime、不监听，`ApiServer` 可以再次尝试。`HttpSwagger` 委托
`install_docs`，默认从内嵌资源安装，不读取 UI 文件。非法路径或路由冲突时
原子失败、不留下部分文档路由；修正预检失败的原因后，可使用同一个未消费的
`PreparedApi` 重试。外置文件只用于显式自定义策略，见使用指南。

策略安装成功后，`ApiServer` 才创建底层 server 并尝试启动；这一步会把实例
置为单次初始化，即使监听失败也不能再次 `start`。监听失败返回
`transport_error`，底层 router 已消费；`stop()` 只停止当前实例、不支持
restart。之后必须重新 build API 并创建新的 server。自定义策略的半注册副作用
不由通用 `ApiServer` 回滚，实现者必须自行保证失败可重试或明确不可重试。

## 离线导出

```bash
./build/api-docs/examples/cpp/api/example_api_e1_users \
  --export /tmp/galay-openapi.json
```

`--export` 在 `ApiServer` 构造、策略安装、Runtime 构造和监听之前执行并退出。
它不安装 UI、不读取 UI 文件、不连接数据库，也不启动服务；文档与
`/openapi.json` 使用相同注册信息。文件先写入目标目录的唯一临时文件，检查写入和关闭结果，
然后 rename，失败时检查临时文件清理结果。目标目录必须已经存在。

## 安装后消费

安装启用了 API 的 Galay 构建后，独立工程只使用安装包，不引用源码树，
也不添加资源路径编译宏：

```cmake
cmake_minimum_required(VERSION 3.28)
project(api_consumer LANGUAGES CXX)
find_package(galay CONFIG REQUIRED)
add_executable(api_consumer main.cc)
target_link_libraries(api_consumer PRIVATE galay::api)
```

应用使用默认 `HttpSwagger` 即可提供文档：

```cpp
#include <galay/cpp/galay-api/api_server.h>
#include <iostream>
#include <utility>

galay::api::ApiServer<galay::api::HttpSwagger> server(
    galay::http::HttpServerBuilder()
        .host("127.0.0.1").port(8087)
        .ioSchedulerCount(1).parallelSchedulerCount(1).buildConfig());
auto started = server.start(std::move(prepared));
if (!started) {
    std::cerr << started.error().message << '\n';
    return 1;
}
```

`prepared` 同样来自成功的 builder；server 必须保持存活，主线程在应用
退出时调用 `stop()`，不能在局部 helper 返回时立即销毁运行中的服务。
完整独立消费验证源码见
`test/cpp/api/consumer`。构建消费工程时通过 `CMAKE_PREFIX_PATH` 指向安装
前缀。UI 字节已经包含在 API 库中，部署时遵循正常的可执行文件及链接库
部署要求，无需复制额外 UI 文件。版本、来源、许可证及校验信息同时保留在
`${prefix}/share/galay/swagger-ui`，该目录不是默认文档服务的运行期依赖，
`find_package(galay)` 不检查其存在性。移动安装前缀或更换工作目录不需要
重新配置 UI 路径。
