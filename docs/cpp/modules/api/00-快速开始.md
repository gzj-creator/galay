# 快速开始

## 构建和运行

要求 C++23、CMake >= 3.28、现有 HTTP/kernel 依赖及 serde 0.4.0。源码树已固定
`thirdparty/serde` 到 `v0.4.0`，提交 `e93269257f04166db056da4ef9ee893d8cc096bf`。
新 checkout 可初始化 submodule；已有本地改动时先审查，不覆盖未提交工作。

```bash
git -C thirdparty/serde describe --tags --exact-match
git -C thirdparty/serde rev-parse HEAD
cmake -S . -B build/api-docs -G Ninja \
  -DCMAKE_CXX_COMPILER=g++-14 \
  -DGALAY_BUILD_API=ON -DGALAY_BUILD_HTTP=ON -DGALAY_BUILD_SERDE=ON \
  -DGALAY_BUILD_SSL=ON -DGALAY_BUILD_HTTP2=ON \
  -DGALAY_BUILD_EXAMPLES=ON -DBUILD_TESTING=ON
cmake --build build/api-docs --target example_api_e1_users api_t12_native_builder -j1
ctest --test-dir build/api-docs -R '^api.native_builder$' --output-on-failure
./build/api-docs/examples/cpp/api/example_api_e1_users --port 8087
```

只需 API 时可关闭其他数据库、协议模块、C ABI 和 benchmark。低内存环境使用
`-j1`。示例默认监听 loopback，在另一终端请求：

```bash
curl 'http://127.0.0.1:8087/users/1?verbose=true'
curl -X POST 'http://127.0.0.1:8087/users' \
  -H 'Content-Type: application/json' -d '{"name":"Lin","email":null}'
```

访问 `http://127.0.0.1:8087/docs` 使用官方 UI，`/openapi.json` 返回同一份预生成
文档。资源已编译进 API 库，不依赖部署资源目录或 CDN。

## 原生入口

以下片段使用完整示例的 DTO、注册函数和错误输出函数：

```cpp
#include <galay/cpp/galay-api/api_router.h>
#include <galay/cpp/galay-http/server/http_server.h>

galay::http::HttpServerBuilder<true> builder;
builder.host("127.0.0.1").port(8087)
    .io_scheduler_count(1).parallel_scheduler_count(1);
builder.api_info({.title = "Users API", .version = "1.0.0"});
auto registered = users::register_api(builder);
if (!registered) return report_error(registered.error());
auto built = builder.build();
if (!built) return report_error(built.error());
auto started = (*built)->start();
if (!started) return report_error(started.error());
```

server 保持存活直到应用控制循环退出，再调用 `stop()`。`build()` 返回
`ApiResult<std::unique_ptr<HttpServer>>`，先预检文档和资源，后构造 Runtime；
监听发生在 `start()`。成功构建冻结注册，managed 启动是单次操作。构建失败
可修正配置后重试；启动失败或停止后重新创建 builder/server。

关闭文档使用 `HttpServerBuilder<>`，不调用 `api_info` / `docs`，同一注册函数
和 typed handler 保持不变。关闭模式不生成文档，也不提供 `export_openapi()`。
只导出传输配置供原生 handler/static 模式使用时调用 `build_config()`，该配置
不包含 builder 已登记的路由或文档。

## 四种传输

同一个示例和 `users::register_api(builder)` 支持 `--transport http|https|h2c|h2`。
未编译对应模块时明确失败。以下端口仅作示例，一次启动一种模式：

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 2 -subj /CN=localhost \
  -addext 'subjectAltName=DNS:localhost,IP:127.0.0.1' \
  -out /tmp/galay-api-test.crt -keyout /tmp/galay-api-test.key

./build/api-docs/examples/cpp/api/example_api_e1_users --transport https --port 18087 \
  --cert /tmp/galay-api-test.crt --key /tmp/galay-api-test.key
curl --http1.1 --cacert /tmp/galay-api-test.crt 'https://127.0.0.1:18087/users/1'

./build/api-docs/examples/cpp/api/example_api_e1_users --transport h2c --port 18087
curl --http2-prior-knowledge 'http://127.0.0.1:18087/users/1'

./build/api-docs/examples/cpp/api/example_api_e1_users --transport h2 --port 18087 \
  --cert /tmp/galay-api-test.crt --key /tmp/galay-api-test.key
curl --http2 --cacert /tmp/galay-api-test.crt -v 'https://127.0.0.1:18087/users/1'
```

curl 请求在另一终端执行；HTTP/2 命令需要具备 HTTP/2 支持的 curl。H2 检查
ALPN `h2`，浏览器需信任本地测试证书。Chromium 不使用明文 h2c prior knowledge，
因此 h2c 使用真实 HTTP/2 客户端验收，不将 fallback 404 算作支持。

## 离线导出与安装

```bash
./build/api-docs/examples/cpp/api/example_api_e1_users --export /tmp/galay-openapi.json
```

导出在 `build()` 前执行并退出，不构造 Runtime、不监听、不安装 UI、不读取
TLS 文件。文件先写同目录临时文件，检查写入和关闭，再 rename；失败检查
临时文件清理结果，目标目录须已存在。

安装后独立工程：

```cmake
cmake_minimum_required(VERSION 3.28)
project(api_consumer LANGUAGES CXX)
find_package(galay CONFIG REQUIRED)
add_executable(api_consumer main.cc)
target_link_libraries(api_consumer PRIVATE galay::api)
# HTTP/2 consumers additionally link galay::http2.
```

通过 `CMAKE_PREFIX_PATH` 指向安装包，使用同一原生 builder 入口，无资源路径
宏或额外 UI 文件。来源、许可证和校验信息另安装到 `share/galay/swagger-ui`，
默认运行和 `find_package(galay)` 不检查它。实际搬迁消费验收见 `api.install_consumer`。
