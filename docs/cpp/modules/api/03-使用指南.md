# 使用指南

## 策略选择和启动

`ApiServer<>` 等价于 `ApiServer<NoSwagger>`：不自动注册 `/docs` 或
`/openapi.json`，但不移除已经手动安装的文档路由，builder 仍生成文档。
需要公开 JSON 和离线 UI 时，显式选择 `ApiServer<HttpSwagger>`，默认路径
无需传入策略参数。需要定制路径时传入 `DocsConfig`；下例的 `prepared`
来自成功的 `ApiBuilder::build()`：

```cpp
auto config = galay::http::HttpServerBuilder()
    .host("127.0.0.1").port(8087)
    .io_scheduler_count(1).parallel_scheduler_count(1).build_config();
galay::api::ApiServer<galay::api::HttpSwagger> server(config,
    galay::api::HttpSwagger(galay::api::DocsConfig{
        .spec_path = "/v1/schema~private.json",
        .ui_path = "/help/api-v1"}));
auto started = server.start(std::move(prepared));
if (!started) return std::unexpected(std::move(started.error()));
```

包含 `api_server.h` 和 `<utility>`。`build_config()` 和 `ApiServer` 构造均
不创建 Runtime；不要改成底层 builder 的 `build()`。`start` 先验证
`PreparedApi` 并安装策略；验证或策略安装失败时仍未初始化，不创建 Runtime
或监听，且可再次尝试。策略安装成功后才创建 Runtime 和监听，并将实例置为
单次初始化；即使监听失败，重复 `start` 也返回 `ApiErrorCode::kServerError`。监听失败
本次返回 `ApiErrorCode::kTransportError`，`stop` 只停止底层服务，不提供 restart；重启
需要重新 build API 和新 server。server 必须存活到服务退出。

在控制线程调用 `stop()`，不要在业务协程中同步调用。typed 路由停止时先
停止接收并中断连接 IO，再等待请求/stream handler 完成，最后释放 Runtime；
排空期间定时器仍运行。reset 或停止不会抢占任意业务 handler，应用必须
保证 handler 最终返回并管理独立后台任务。重复 `stop()` 无副作用，但不
恢复 `start()` 能力。

`HttpSwagger` 只委托 `install_docs`，文档仍是 builder 预先生成的同一份
不可变数据。默认资源已编译进 API 库，不读取文件。非法路径或路径冲突时
原子失败且不消费 router；修正预检失败原因后可重试同一个未消费的
`PreparedApi`。不要先手动 `install_docs` 再用
`HttpSwagger` 自动安装；需要手动控制安装时，可与 `NoSwagger` 或原有
`HttpServer` 组合。

自定义策略需满足 `ApiDocsPolicy`，可移动即可，不要求复制、默认构造或
继承；显式传入所需配置和策略。通用 server 不可能回滚任意自定义
`install` 的副作用，实现者必须自己保证失败不留下半注册状态。handler
不能保存 `PreparedApi&`、builder 或调用方临时策略的引用；捕获不可变
共享文档和资源，或借用地址稳定的 server 自持策略，其生命周期覆盖
底层服务停止和销毁。不要在请求热路径读取 UI 文件或修改路由。

`NoSwagger` 省去自动文档安装，不省去 `galay-api` 的 serde 依赖或 builder
文档生成成本。仅使用底层 `galay-http` 的工程仍无需依赖 `galay-api`。

## 参数来源和 DTO

DTO 使用 serde 的 `REFLECT_FIELDS` 或 `reflect_fields` 注册一次。外部
字段名、description、数值/字符串/容器约束同时作用于 schema 与编解码。
例如 `field_options<std::string>{.min_length=1,.max_length=40}` 的长度按
Unicode 标量计数，不是 UTF-8 字节数。

- path 参数必须与 `:name` 一一匹配，始终 required，不能是 optional。
- query 支持 string、整数、浮点、bool、已登记 enum 及其 optional。
- bool 只接受 `true` / `false`；数值必须完整消费且不能溢出。
- 未被 path/query 绑定的 DTO 字段形成 JSON object body，不要求客户端
  在 body 重复 path/query 字段。GET/HEAD 不允许剩余 body 字段。
- 有实际 JSON body 时要求 `Content-Type: application/json`；无 body 时
  不要求 Content-Type。必需 body 缺失、畸形 JSON、重复键、未知字段和
  约束失败均显式报错。
- 缺失 optional 保留 DTO 默认值并验证；显式 JSON null 清空 optional。
  query 不把文本 `null` 当作空值。输出的空 optional 编码为 JSON null。

数组和嵌套对象可在 JSON body 中使用，query 数组、重复参数键数组和
multipart 不在首版范围内。Serde 的选择解码失败可能已部分赋值，绑定层
丢弃该次 input，不通过异常或回滚掩盖失败。

query 直接复用现有 `HttpRequestHeader::args()` 单值 map，不重新解析 URI。
重复键不能绑定为多个值；尾部空值可能被 HTTP parser 丢弃，`+` 不转换
为空格，百分号解码发生在分割键值之前，所以编码后的 `&` 或 `=` 也可能
影响参数分割。首版不承诺完整的 form/query URI 语义，不执行第二次解码；
需要保留这些字符、空字符串或多值时使用 JSON body，不扩大 HTTP 热路径。

## 路径和冲突

API 路径使用 `/users/:id`，文档输出 `/users/{id}`。四种传输支持同一组 REST
方法，不支持 CONNECT/PRI/UNKNOWN，拒绝通配符、空段、重复参数、
URI dot segment、歧义同形路径和重复 operationId。

文档 `spec_path` 和 `ui_path` 必须是以 `/` 开头的规范静态路径，仅接受
ASCII 字母、数字、`-`、`_`、`.`、`~` 及 `/` 分隔符。拒绝 dot segment、
空段、尾部斜线（根 `/` 除外）、百分号编码、query、fragment、反斜线、
控制字符、引号、非 ASCII 和 router 参数 / 通配符，不做暗中归一化。
这是 HTTP router 的实际静态路径边界；恶意 HTML/JS 片段显式失败。
初始化配置通过 serde JSON serializer 输出，HTML 只插入已经验证的
安全路径，不手写 JSON 转义。

例如 `spec_path="/v1/schema~private.json"` 和 `ui_path="/help/api-v1"`
可正常使用。非根 UI 额外注册尾斜线别名；资源使用根相对 URL，所以
`/docs` 与 `/docs/` 不会把 JS/CSS 请求错误地落到站点根目录。
UI 可挂在 `/`，此时资源为 `/swagger-ui.css` 等，spec 必须使用其他路径。
基路径和生成的资产路径均不能超过 HTTP router 的 2048 字节限制。

启用 `HttpSwagger` 或任一文档安装器时，文档路径是保留空间；
任何方法的 endpoint 或已存在 router handler
（包括参数或通配符匹配）占用这些具体路径时安装失败。已有业务路由
不会被覆盖。不要在服务运行后手动增删 `PreparedApi::router` 或再次安装。

## 内嵌资源和离线部署

固定官方 npm 包 `swagger-ui-dist@5.17.14`，许可证 Apache-2.0。
资源来源、许可证、npm integrity、归档 SHA256 和逐文件 SHA256 记录在
`assets/swagger-ui`，原始官方文件没有改写。构建时检查 `SHA256SUMS` 中七个
上游文件的 SHA256，再把必要 CSS、bundle、standalone preset、两个
favicon 以及 `LICENSE`、`NOTICE`、`README.md`、`SHA256SUMS` 共九个资源
编译进可选 API 模块。缺失文件、空文件、非法校验清单或哈希不匹配使资源
生成失败；API 关闭时不引入此生成依赖。版本固定，不在构建或启动时下载。
HTML / initializer 在启动前安装文档路由时生成。

`HttpSwagger{}` 和 `install_docs(api)` 不需要任何资源目录，也不读取
UI 文件。部署只需满足正常的可执行文件及链接库依赖；移动部署目录、
更换工作目录或没有 `share/galay/swagger-ui` 都不会使默认文档资源失效。
安装包将来源、许可证、版本及校验信息保留在
`${prefix}/share/galay/swagger-ui`，同时这些信息可从 UI 路径下的元数据
路由读取；默认服务及 `find_package(galay)` 不依赖这个安装目录。

默认 UI 和 OpenAPI 都从同一服务器加载。初始化显式设置
`validatorUrl:null`、`persistAuthorization:false` 和
`queryConfigEnabled:false`，禁用在线 validator、持久授权和查询参数配置
覆盖。没有 CDN fallback，没有默认 petstore 请求；文档中的外部链接仅
展示，不在页面初始化时加载。应用若自行登记外部 `$ref`、server、OAuth
或其他外网目标，不属于本地资产承诺，浏览器会受部署网络策略约束。

## 显式文件策略

需要由应用部署和管理资源时，可实现自己的策略，不修改 `HttpSwagger` 的
默认行为。下面的 `FileDocsPolicy` 属于应用示例，不是框架内置类型：

```cpp
#include <galay/cpp/galay-api/api_server.h>
#include <string>
#include <utility>

class FileDocsPolicy {
public:
    explicit FileDocsPolicy(std::string directory, galay::api::DocsConfig config = {})
        : directory_(std::move(directory)), config_(std::move(config)) {}

    galay::api::ApiResult<void> install(galay::api::PreparedApi& api) const
    {
        return galay::api::install_docs_from_directory(api, config_, directory_);
    }

private:
    std::string directory_;
    galay::api::DocsConfig config_;
};

static_assert(galay::api::ApiDocsPolicy<FileDocsPolicy>);
```

使用前面的 HTTP `config` 和成功 build 的 `prepared`：

```cpp
galay::api::ApiServer<FileDocsPolicy> server(config, FileDocsPolicy("/opt/app/api-ui"));
auto started = server.start(std::move(prepared));
if (!started) return std::unexpected(std::move(started.error()));
```

目录必须同时包含 `swagger-ui.css`、`swagger-ui-bundle.js`、
`swagger-ui-standalone-preset.js`、`favicon-16x16.png`、`favicon-32x32.png`、
`LICENSE`、`NOTICE`、`README.md` 和 `SHA256SUMS`。每个文件必须是非空普通
文件，最多 16 MiB；提供与部署资源匹配的版本、来源、许可及校验信息。
文件安装器检查加载结果，不把自定义资源当作已通过官方构建期哈希校验。
加载、读取、关闭失败保留具体文件及系统错误。

缺少任一文件会返回 `ApiErrorCode::kResourceError`，绝不补用内嵌资源或 CDN。所有文件
在启动前一次读入内存，完整预检路由后才注册；失败不留下部分文档路由，
不创建 Runtime、不监听。修复目录后可重试同一个未消费的 `PreparedApi`。
成功启动后目录移动或删除不影响当前进程；下次启动仍需显式目录有效。
请求期间不读取文件或热更新。

重复文档安装返回 `ApiErrorCode::kRouteConflict`，而已经进入底层启动的 `ApiServer` 上
重复 `start` 返回 `ApiErrorCode::kServerError`，两者不是同一错误。通用 server 不回滚
任意自定义策略的副作用；这里的原子性来自文件安装器自身。

## 边界和部署

四种传输使用同一份 DTO、`ApiBuilder::add` 注册及 `PreparedApi` 契约。
每个 server 消费一份 prepared；要同时监听多个传输，使用同一个注册函数
分别 build，不能多次移动已经消费的 router。默认 HTTP/1 不变；TLS 选择
`HttpsServerConfig` 或 `H2ServerConfig` 并提供原生证书/私钥配置。

h2c 客户端必须使用现有引擎的 prior knowledge，不要求 HTTP/1 Upgrade。
Chromium 对明文 origin 使用 HTTP/1，不会因为服务提供 h2c 就协商 HTTP/2；
原生 HTTP/1 fallback 的 404 不算 h2c Swagger 或 Try it out 验收。需要浏览器
直连 HTTP/2 时使用 H2 over TLS，确认 ALPN `h2` 和浏览器实际响应协议。
本地自签证书的浏览器例外仅用于测试，不是生产信任配置；生产使用受信任
证书并保留 hostname/CA 验证。HTTPS 的协议是 HTTP/1 over TLS，不冒充 H2。

四种传输的文档、HTML、初始化脚本和九项资源均在本地同源提供；
`NoSwagger` 不自动暴露它们，路径冲突和显式目录缺项的失败规则相同。
OpenAPI 保持 3.1.0，Swagger UI 保持 5.17.14。`NoContent`
用于无 body 成功输出，HEAD 和 204/205 的实际输出与注册语义一致。
示例是确定性演示，无数据库、持久用户存储或通用业务校验框架。
