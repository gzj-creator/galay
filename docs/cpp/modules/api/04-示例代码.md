# 用户 API 示例

源码 `examples/cpp/api/e1_users.cc`，CMake target `example_api_e1_users`，Bazel
target `//examples/cpp/api:users`。Bazel 接线与实际验收范围见验证记录。

| 请求 | 输入 | 成功 | 业务失败 |
| --- | --- | --- | --- |
| `GET /users/:id` | path id、可选 query verbose | 200 UserDto | 404 用户不存在 |
| `POST /users` | JSON name、可选 email | 201 UserDto | 409 名称被保留 |

GET 提供固定 ID 1、2，`verbose=true` 返回详情，否则详情为 null。POST 返回
演示 ID 100，不保存数据库。name 为 1 到 40 个 Unicode 标量，email 最多 254，
admin 为保留名称。serde 字段约束同时用于绑定和文档。

```bash
./build/api-docs/examples/cpp/api/example_api_e1_users --port 8087
curl 'http://127.0.0.1:8087/users/2?verbose=true'
curl -i 'http://127.0.0.1:8087/users/999'
curl -i 'http://127.0.0.1:8087/users/not-a-number'
curl -i -X POST 'http://127.0.0.1:8087/users' \
  -H 'Content-Type: application/json' -d '{"name":"Lin","email":null}'
```

输入错误为 400，body 媒体类型不正确为 415，业务错误使用稳定 code/message。
独立协程 handler 返回 `Task<ApiResult<UserDto>>`，不直接发送或关闭连接。

## 构建与传输

`users::register_api(Builder&)` 在所选原生 builder 上登记两项 typed 操作。
`run_server` 设置 ApiInfo，检查注册、`build()`、`start()`，主线程等待退出信号
后停止原生 server。HTTP/HTTPS/h2c/H2 只切换 builder，DTO、handler 和契约不变。
示例使用 `<true>` 自动提供文档；复用注册函数到 `Builder<>` 时请求行为保留，
文档路由不安装。默认路径冲突可以修正后重试构建；已尝试启动则需新实例。

`/openapi.json` 只包含两项 typed 操作，不从普通 handler 推测 DTO。文档与
资源在 server 构建前准备，请求热路径不生成 schema 或读取文件。

## 命令行和导出

`--port <1-65535>` 默认 8087；`--transport http|https|h2c|h2` 默认 http。
TLS 使用 `--cert <pem>` / `--key <pem>`；未启用模式明确失败。未知参数、重复
参数、缺值和非法端口报错，不用 atoi 静默截断。

```bash
./build/api-docs/examples/cpp/api/example_api_e1_users \
  --export /tmp/galay-users-openapi.json --port 18087
```

导出在 `build()` 前执行，不需要资源目录、证书/私钥，不占用端口。唯一临时
文件在写入和关闭成功后 rename，失败检查清理结果，不留下假完整文档。
正常服务使用 SIGINT/SIGTERM 退出，协程 handler 不做线程 sleep 或阻塞同步。

安装后编译相同源码链接 `galay::api`，HTTP/2 分支另链接 `galay::http2`，无
资源路径宏。移动安装目录、改变工作目录不会改变内嵌资源；外置资源直接
通过原生 builder 的 `docs(config, directory)` 配置，完整九项缺一即失败。
实际独立消费测试入口为 `api.install_consumer`。
