# 用户 API 示例

源码：`examples/cpp/api/e1_users.cc`。
CMake target：`example_api_e1_users`；Bazel target：
`//examples/cpp/api:users`。Bazel、module 和 mcpp 组合未实际验收，接线不等于
通过构建或运行验证。

## 接口

| 请求 | 输入 | 成功 | 声明的业务失败 |
| --- | --- | --- | --- |
| `GET /users/:id` | path `id`，可选 query `verbose` | 200 `UserDto` | 404 用户不存在 |
| `POST /users` | JSON `name`，可选 `email` | 201 `UserDto` | 409 名称被保留 |

GET 示例固定提供 ID 1 和 2。`verbose=true` 时输出详情，省略 query 时
详情为 null。POST 返回演示 ID 100，不保存到数据库，后续 GET 不查询
这次创建结果。`name` 的长度为 1 到 40 个 Unicode 标量，`email` 上限
254 个标量；`admin` 为业务保留名称。约束由 serde 字段 options 登记，
与文档和实际绑定使用相同定义。

```bash
./build/api-docs/examples/cpp/api/example_api_e1_users --port 8087
curl 'http://127.0.0.1:8087/users/1'
curl 'http://127.0.0.1:8087/users/2?verbose=true'
curl -i 'http://127.0.0.1:8087/users/999'
curl -i 'http://127.0.0.1:8087/users/not-a-number'
curl -i -X POST 'http://127.0.0.1:8087/users' \
  -H 'Content-Type: application/json' -d '{"name":"Lin"}'
curl -i -X POST 'http://127.0.0.1:8087/users' \
  -H 'Content-Type: application/json' -d '{"name":"admin","email":null}'
```

绑定错误为 400；有 body 而媒体类型不正确为 415；业务错误使用
`code=business_error` 和明确 message。成功响应的 optional 字段保持存在，
空值输出 null。业务 handler 是独立协程函数，返回
`Task<ApiResult<UserDto>>`，不直接发送或关闭 HTTP 连接。

## ApiServer 启动

示例通过 `ApiBuilder` 一次登记上述两个 typed endpoint，成功 build 后
使用 `ApiServer<HttpSwagger>`，不再直接创建 `HttpServer` 或调用
`install_docs`。以下对应实际服务分支；`api` 已检查，类型为
`ApiResult<PreparedApi>`，`options` 来自已检查的参数解析：

```cpp
ApiServer<HttpSwagger> server(galay::http::HttpServerBuilder()
    .host("127.0.0.1").port(options->port)
    .io_scheduler_count(1).parallel_scheduler_count(1).build_config());
auto started = server.start(std::move(*api));
if (!started) return report_error(started.error());
```

包含 `api_router.h`、`api_server.h`、`docs.h` 和 `<utility>`，使用
`galay::api` 命名空间。`build_config()` 不创建 Runtime，server 构造也不
创建 Runtime；`start` 先执行 `HttpSwagger::install`，它委托现有
`install_docs`，原子地检查并安装文档路由后才创建并启动底层 server。
策略失败时仍可用同一个未消费的 `PreparedApi` 重试；策略成功后实例进入
单次初始化，即使底层监听失败也不能再次 `start`。

要保留 typed GET/POST 但不自动公开文档，将 server 声明替换为：

```cpp
ApiServer<> server(galay::http::HttpServerBuilder()
    .host("127.0.0.1").port(options->port)
    .io_scheduler_count(1).parallel_scheduler_count(1).build_config());
```

默认 `NoSwagger` 不加载 UI、不自动注册文档，但也不删除手动安装的路由；
离线导出不受影响。不要将上述两种声明同时用于同一个已消费的 prepared。
`HttpSwagger` 默认使用内嵌官方资源，路径预检失败时可修正后重试；自定义
策略必须自行保证失败不留下半注册状态，不能借用 `PreparedApi&`，通用
server 不提供副作用回滚。
一旦策略安装成功并开始底层初始化，实例不能重复 `start`，`stop` 也不支持
restart。底层失败返回 `ApiErrorCode::kTransportError`，router 已消费；再次启动需要新
server 和重新 build 的 API。自定义策略的失败副作用不属于 `ApiServer` 的
回滚范围。

服务模式中 `/openapi.json` 覆盖两个 typed 操作，不从原始 router handler
推测 DTO；资源和生成文档在启动前准备，请求期间不生成 schema 或读磁盘。
官方 UI 的字节已在构建时编译进 API 库，启动时也不读取 UI 文件。

## 命令行和导出

`--port <1-65535>` 使用独立端口，默认 8087。
`--export <path>` 在 `ApiServer` 构造、文档策略安装、Runtime 创建和监听前导出并退出。
`--help` 输出命令格式。未知参数、重复参数、缺值或非法端口返回错误，
不会使用 `atoi` 静默截断或溢出。

```bash
./build/api-docs/examples/cpp/api/example_api_e1_users \
  --export /tmp/galay-users-openapi.json --port 18087
```

这个命令不要求资源目录存在，也不占用 `18087`。写入失败不留下冒充
完整文档的目标文件；临时文件清理失败也报告具体原因。
正常服务模式用 SIGINT / SIGTERM 请求退出，由主线程检查 server 状态，
停止 HTTP runtime。协程 handler 中没有线程 sleep 或阻塞同步锁。

安装后编译同一示例源码只需 `find_package(galay)` 和链接 `galay::api`，
不需要资源路径编译宏或额外 UI 文件。更换工作目录、移动部署目录不会改变
内嵌资源来源；仍须按正常方式部署可执行文件及其链接库。
需要外置资源时，应用实现文件策略并显式委托 `install_docs_from_directory`，
提供完整九项文件，缺项失败而不回退内嵌资源；完整代码见使用指南。
安装后独立消费测试入口为 `api.install_consumer`，实际验收结果见验证记录。
