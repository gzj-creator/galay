# 05-性能测试

> **正式对标政策（2026-08-21）**：项目正式外部对标唯一采用 Boost.Asio C++
> 协程（`co_spawn`/`awaitable`）。本页只记录 C ABI 内部基线；libpq/C++ 对照属于
> 历史或内部验证，不参与竞品排名。

## 基准入口

`benchmark/c/postgres/b1_query_pressure.c` 通过 PostgreSQL C ABI 对真实实例执行
simple query 压测，构建 target 为 `benchmark_c_postgres_query_pressure`。

每个 client 使用独立的 `galay_postgres_client_t` 和 C coroutine。基准默认分配与
client 数相同的 IO scheduler，并要求 `io_schedulers >= clients`，避免把多个 client
共享 owner scheduler 的调度竞争混入当前查询吞吐口径。

计时前完成建连、认证和每 client 32 次预热；计时窗口包含 query API 及其内部完整
result-set 解码，不包含 runtime 启动、建连、预热和连接关闭。每次 query 返回后还会
遍历所有 value 并累计 bytes 做结果校验：该校验计入 QPS 的总 elapsed，但不计入单次
query latency sample。失败查询或关闭失败会使进程返回非零。

## 构建与运行

```bash
cmake -S . -B build/postgres-c-release \
  -DCMAKE_BUILD_TYPE=Release \
  -DBUILD_TESTING=OFF \
  -DGALAY_BUILD_C_API=ON \
  -DGALAY_BUILD_POSTGRES=ON \
  -DGALAY_BUILD_BENCHMARKS=ON \
  -DGALAY_ENABLE_CPP23_MODULES=OFF
cmake --build build/postgres-c-release \
  --target benchmark_c_postgres_query_pressure -j4

export GALAY_POSTGRES_HOST=127.0.0.1
export GALAY_POSTGRES_PORT=5432
export GALAY_POSTGRES_USER=postgres
export GALAY_POSTGRES_PASSWORD=postgres
export GALAY_POSTGRES_DB=postgres

./build/postgres-c-release/benchmark/c/postgres/benchmark_c_postgres_query_pressure \
  --clients 4 --queries 10000 --warmup 32
```

可用参数为 `--clients`、`--queries`、`--warmup`、`--io-schedulers`、
`--timeout-ms` 和 `--sql`。对应环境变量为
`GALAY_POSTGRES_BENCH_CLIENTS`、`GALAY_POSTGRES_BENCH_QUERIES`、
`GALAY_POSTGRES_BENCH_WARMUP`、`GALAY_POSTGRES_BENCH_IO_SCHEDULERS`、
`GALAY_POSTGRES_BENCH_TIMEOUT_MS` 和 `GALAY_POSTGRES_BENCH_SQL`。C socket ABI
当前要求 `GALAY_POSTGRES_HOST` 使用数值 IPv4/IPv6 地址。

## 本机结果（2026-08-12）

- 系统：Linux 7.0.0-28-generic，12 个可用逻辑 CPU，Intel Core i7-14700K。
- 构建：GCC 14.2.0、CMake 3.28.3、Release `-O3 -DNDEBUG`，epoll backend。
- PostgreSQL：16.14，`max_connections=100`、`shared_buffers=128MB`、
  `synchronous_commit=on`、`fsync=on`、`jit=on`。
- workload：`SELECT 1`，4 clients、4 IO schedulers、每 client 32 次预热和
  10000 次计时查询；每次运行共 40000 次查询。
- 每次使用 `taskset -c 0-3` 固定到相同 CPU 集合；未固定 CPU 频率或关闭 turbo。

三次运行均为 `40000/40000` 成功，结果如下：

| run | QPS | elapsed s | p50 ms | p95 ms | p99 ms |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 8053.75 | 4.966633 | 0.390 | 0.872 | 1.271 |
| 2 | 8415.46 | 4.753155 | 0.387 | 0.852 | 1.234 |
| 3 | 7943.46 | 5.035589 | 0.400 | 0.882 | 1.289 |
| 中位数 | 8053.75 | 4.966633 | 0.390 | 0.872 | 1.271 |

另以 8 clients、8 IO schedulers、每 client 5000 次查询执行一次并发稳定性检查：
`40000/40000` 成功，`10226.44 QPS`，p50/p95/p99 为
`0.620/1.448/2.076 ms`。该单次结果不纳入上表中位数。

该数据只代表本机明文 loopback、只读 simple query 和当前 C API 实现。它不等价于
远程网络、TLS、写入 SQL、prepared statement、pipeline 或 pool 的性能，也没有与
libpq/C++ API 做同轮交替对照；跨机器或跨版本比较应固定 CPU 频率、服务端配置、SQL
和连接拓扑后重新采样。
